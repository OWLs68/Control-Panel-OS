## 1. Що будуємо

**Roma OS** — інтерфейс операційної системи Roman AI OS. Не life-tracker,
не щоденник, не admin-панель для розробника.

Ядро продукту — стан і робота самої ОС. Особисті інструменти
(задачі, звички, фінанси, Вечір, Я, нотатки) — **модулі**, які підключаються
за потребою і не піднімаються вище ядра.

Мобільний сценарій головний: з телефона видно, що відбувається, що потребує
Романа, що роблять агенти, що з проєктами — і можна сказати щось Crow.

## 4. Мокап

> **Це ескіз композиції, не еталон механік.** Він показує, що і де на екрані.
> Як воно має працювати — дивитись у NeverMind. Див. `HANDOFF.md`, розділ 0.

`mockup.html` — самодостатній файл, відкривається подвійним кліком.
Зображення Crow вшиті всередину, зовнішніх залежностей немає (крім шрифтів
із Google Fonts).

Опублікована версія: <https://claude.ai/artifact/FnLroz2auDqiDPm9en9GGS>

Що в ньому показано: шапка, зона Crow з темною бульбашкою і кнопками,
рядок метрик, «Потребує мене», карта системи, стан, цитата, «У роботі»,
швидкі дії, поле Crow, закріплений барабан, шторка модулів.
Вкладки Agents / Projects / Events заповнені; Memory і особисті модулі —
заглушки, що вмикаються через «Модулі».

`assets/` — оптимізовані зображення Crow: `crow-front` (базова поза),
`crow-idle` (3/4), `crow-talk` (жест рукою). Фон обрізано, ~24–33 КБ кожне.
Оригінали були по 2 МБ — для офлайн-кешу PWA це неприйнятно, тож у код
беруться саме ці.

## 5. Що перевикористовуємо з NeverMind

Клон лежить публічно: `OWLs68/NeverMind`. Перед написанням будь-якої
механіки — спершу читати, як це вже зроблено там.

**Геометрія екрана (критично).** `html, body { height:100%; overflow:hidden }` —
документ не скролиться взагалі. Кожна сторінка `position:absolute; inset:0;
overflow-y:auto` — скрол живе всередині. `#tab-bar` — `position:fixed`.
Висота панелі міряється в JS і кладеться в `--tabbar-h`.
*Це вже один раз призвело до бага: панель опинилась за межами екрана,
бо контейнер ріс під вміст.*

**Барабан** — `rebuildDrumTabbar` / `applyDrum3D` / `setupDrumTabbar`
у `src/core/nav.js`. Фізика з інерцією, snap у центр, поворот по дузі.
Там же `getActiveTabs` / `saveActiveTabs` (ключ `nm_active_tabs`)
і шторка вибору вкладок `openTabSelector`.

**Табло агента** — `src/owl/board.js`: згортання свайпом, стани, пріоритети
(normal / urgent / success), стрічка чіпів зі стрілками.

**Чіпи** — `src/owl/chips.js`. Дії: `nav`, `clarify_save`, `chat`, `complete`.
Контрольний тест: «чи економить цей чіп набір тексту? якщо ні — це декорація».

**Модалки** — `src/ui/modal-overlay-sync.js` + специфікація в
`docs/DESIGN_SYSTEM.md`: три способи закриття, картка їде за пальцем,
і перелік того, що на iOS ламається (вкладений blur, глобальний `:active`,
`margin-bottom` для виїзду, `overscroll-behavior: contain`).

**Взаємодія без inline-обробників** — `src/core/delegation.js` (`data-action`)
і `src/ui/touch-detect.js` (`data-swipe-detect` / `data-tap-detect`).
Рендер-агностичні: переносяться майже дослівно.

**Ще**: `swipe-delete.js`, `checklist.js`, `voice-input.js` (українською),
`keyboard.js` (підйом під клавіатуру на iOS), глобальна анімація натискання.

**Конверт сутності** — `src/core/entity.js`, функція `stampEntity`:
UUID, `created_at`, `updated_at`, `deleted_at`, поле `hlc` під порядок змін.
Готовий фундамент під local-first. Плюс `src/data/entity-factories.js`.

**Межа до LLM** — усі звернення йдуть через одну функцію `openaiFetch`
у `src/ai/core.js`, і в CI є сторож, який стежить, щоб прямих викликів
не з'являлось деінде. Заміна OpenAI → Hermes = зміна **однієї** функції.

**Що НЕ переносимо**: монолітний `index.html`, localStorage як основну базу,
OWL/domain-архітектуру, ключ OpenAI у браузері, екосистему хуків,
палітру NeverMind.

## 7. План Етапу 1

**A. Основа**
1. Зліпок поточного стану в `legacy/control-panel-v1`.
2. Чистий фундамент на базі NeverMind: скелет сторінки, стилі, esbuild, service worker.
3. TypeScript у ту саму збірку — для нового OS-коду.

**B. Вигляд**
4. Токени Graphite Amber. Перевірити контраст `#6D6A65` на `#FFF9F2` для дрібного тексту.
5. Примітиви: картка, кнопка, чіп, поле, порожній стан.

**C. Дані**
6. Конверт сутності + доменні сховища з єдиним контрактом (порт `stampEntity`).
7. Типізовані контракти адаптерів + маркування mock/live.

**D. Crow**
8. Контракт Hermes gateway (типи запит/відповідь/помилка) + заглушка. Без вигаданого бекенда.
9. `CrowCharacter` — компонент з поточним станом, підготовлений під пози/вирази/анімації.
10. Верхня зона: персонаж + бульбашка + чіпи + згортання.
11. Поле Crow на кожній вкладці (голос, підйом під клавіатуру).

**E. Навігація**
12. Реєстр модулів — один опис на модуль (id, підпис, іконка, чи можна ховати, що малювати).
13. Барабан + шторка модулів.

**F. Екрани**
14. Control: Потребує мене / В роботі / Стан системи / Карта системи.
15. Заглушки Agents / Projects / Memory / Events.

**G. Перевірка**
16. Прогін у браузері на розмірі iPhone: скріншоти, переповнення, розміри під палець, безпечні зони, консоль.
17. Lint, збірка, тести.

## 8. Відкриті питання

- Чи лишається окрема вкладка Notes.
- Шрифтова пара — підтвердити або замінити.
- Коли підключати Productivity: одразу після ядра чи паралельно з Agents/Projects.
- Реальний спосіб достукатись до Hermes з телефона (gateway не існує).
- Чи потрібна темна тема взагалі.

## 9. Обмеження середовища, про які варто пам'ятати

- `owls68.github.io` **заблокований** egress-політикою cloud-сесії — перевіряти
  задеплоєний сайт звідти не можна. Тому production smoke-тест винесений
  у CI-job, який ганяється на раннері GitHub.
- Pages деплоїться тільки з `main`: environment `github-pages` має правило,
  що дозволяє деплой лише з default-гілки.
- Chromium у середовищі не збігається версією з `@playwright/test` — шлях до
  нього резолвиться через `scripts/chromium-path.mjs`.
