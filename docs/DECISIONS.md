# Architecture decisions — Control Panel

Короткий журнал рішень, які важко буде відновити з коду. Не дублює README і не є
canonical документом Roman AI OS.

---

## 1. Stack: React + Vite + TypeScript, без UI-фреймворку

**Проблема.** Потрібен встановлюваний PWA з шістьма розділами, adapter layer і
domain-типами, який можна швидко розвивати й не переписувати при підключенні реальних
даних.

**Рішення.** React + Vite + TypeScript + react-router + vite-plugin-pwa. Стилі — звичайний
CSS із custom properties.

**Чому не інакше.**

- *Vanilla JS + esbuild* (як у NeverMind) — мінімум залежностей, але шість екранів із
  роутингом, станами завантаження й темами довелося б писати руками. NeverMind заплатив за
  це файлом `index.html` на 241 KB.
- *SvelteKit / Next* — тягнуть SSR і серверну модель, якої тут немає: панель є статичним
  PWA.
- *Tailwind / CSS-in-JS* — ще одна залежність і конфіг заради того, що на цьому обсязі
  повністю закривають ~15 CSS-змінних.
- *TanStack Query / Redux* — панель read-mostly; вистачає одного хука `useSourced`
  (~60 рядків).

**Наслідок.** 3 runtime-залежності (react, react-dom, react-router-dom).

---

## 2. Adapter layer з обовʼязковим `Sourced<T>`

**Проблема.** Канонічне правило: панель не є другим source of truth і не повинна
створювати враження, що demo-дані є live-даними. Технічно: UI не має залежати від формату
відповідей GBrain / Hermes / GitHub.

**Рішення.** Кожен adapter-метод повертає не голі дані, а конверт:

```ts
Sourced<T> = { data, origin, sourceOfTruth, retrievedAt, staleReason? }
```

**Чому саме так.** Якби origin зберігався глобально (наприклад «застосунок у mock-режимі»),
то гібридний стан — реальний GBrain плюс ще-не-підключений GitHub — довелося б відстежувати
окремо, і перший же частковий деплой зробив би підпис брехливим. Конверт робить чесне
маркування структурно неможливим забути.

---

## 3. `gateway` режим кидає помилку замість тихого fallback на mock

**Рішення.** `createAdapters('gateway')` кидає виняток, бо реалізації ще немає.

**Чому.** Тихий відкат на фікстури дав би панель, яка показує demo-цифри, стверджуючи, що
вони живі. Для інструменту, за яким приймають рішення, це гірше, ніж застосунок, який
відмовляється стартувати.

---

## 4. Mock-дані — snapshot реального стану, а не lorem ipsum

**Рішення.** `src/adapters/mock/fixtures.ts` містить стан, переписаний вручну з canonical
документів (19.09.2026): версії, блокери, черга «чекає на Романа», статус backup.

**Чому.** Абстрактні фікстури приховують проблеми компонування: реальні назви довші,
попереджень більше, ніж хочеться, а «чекає на Романа» насправді має три записи, а не один.
Плата — дані застарівають; тому файл має єдиний `SNAPSHOT_AT` і явне попередження вгорі.

**Межа.** Snapshot — не копія canonical документів. Канон лишається у Drive.

---

## 5. Навігація: bottom tab bar на мобільному, sidebar на desktop

**Рішення.** Обидві навігації в DOM, перемикаються через CSS на 900px. На desktop topbar
ховається — sidebar уже несе бренд і origin-бейдж.

**Чому.** Шість розділів на iPhone — це межа для tab bar, але вона дає доступ до будь-якого
розділу одним дотиком великим пальцем, без відкриття меню. Дублювання в DOM свідоме:
альтернатива — JS-визначення viewport, яке дає стрибок layout при гідратації.

**Виправлено після перевірки в браузері:** спершу sidebar мав англійські підписи, а tab bar
українські. Тепер підписи однакові.

---

## 6. Service worker: NetworkFirst для app shell

**Рішення.** `registerType: 'prompt'`, навігаційні запити — NetworkFirst з таймаутом 3 с,
решта — стандартний precache. Оновлення застосовується лише після дотику користувача.

**Чому.** Пряме перевикористання уроку NeverMind (bug B-73): встановлений на iPhone PWA,
який віддає власний код cache-first, застрягає на старому bundle, і діагностувати це важко.
Мережа виграє, коли вона доступна; кеш — це fallback, а не відповідь за замовчуванням.

---

## 7. Мова: UI українською, код і коментарі англійською

**Рішення.** Усі видимі рядки українською (`lang="uk"`), без i18n-бібліотеки. Ідентифікатори,
коментарі й типи — англійською.

**Чому.** Користувач один і мова одна — i18n-шар вирішував би неіснуючу проблему. Англійські
коментарі лишаються тому, що з кодом працюють AI-клієнти, а canonical документи вже змішують
обидві мови в технічних термінах.

---

## 8. Іконки генеруються Chromium-ом з Playwright

**Рішення.** `scripts/generate-icons.mjs` рендерить SVG і знімає PNG потрібних розмірів.

**Чому.** У середовищі немає ImageMagick / rsvg / sharp, а додавати image-пакет заради
чотирьох PNG невиправдано. Playwright уже є як dev-залежність.

**Побічний ефект.** `scripts/chromium-path.mjs` знаходить наперед встановлений Chromium,
коли його build-номер не збігається з очікуваним для встановленого `@playwright/test`.

---

## 9. Що взято з NeverMind і що свідомо відкинуто

**Взято (адаптовано):**

- стратегію service worker «мережа першою для власного коду» разом із причиною;
- iOS-метатеги: `viewport-fit=cover`, `apple-mobile-web-app-capable`, status bar
  `black-translucent`, `apple-mobile-web-app-title`;
- `env(safe-area-inset-*)` через `max()`/`calc()`;
- `-webkit-tap-highlight-color: transparent` і `touch-action: manipulation`;
- 16px у полях вводу, щоб iOS Safari не зумив viewport при фокусі;
- структуру Playwright: mobile + desktop проєкти, тести проти зібраного застосунку;
- design tokens у `:root`.

**Відкинуто:**

- монолітні `index.html` (241 KB) і `style.css` (62 KB);
- `localStorage` як основну базу даних;
- OWL / domain / AI-архітектуру та стару структуру застосунку;
- екосистему hooks і watchdogs у `.claude/`;
- i18n-baseline як gate у build;
- візуальну ідентичність (glassmorphism, градієнти, Unbounded/Plus Jakarta Sans) — панель
  має власну: спокійні нейтральні поверхні, один стриманий акцент, яскравий колір лише як
  статус.

**Додано понад NeverMind:** справжній `manifest.webmanifest` з maskable-іконкою (NeverMind
покладався тільки на apple-метатеги, тому не був повноцінно встановлюваним на Android).

---

## 10. Шрифти: системний стек, без Google Fonts

**Рішення.** `system-ui` для тексту, `ui-monospace` для ID, версій і метрик.

**Чому.** Вебшрифти означають мережевий запит на старті — для застосунку, який має
працювати офлайн і читатися за кілька секунд, це погана угода. Монопростір для значень
підсилює ідентичність «приладової панелі», нічого не коштуючи.

---

## 11. Відкриті питання

- Формат STATE.md для машинного читання — парсер чи узгоджений frontmatter.
- Чи потрібні панелі write-дії (наприклад, підтвердження L2/L3 просто з UI) — зараз ні.
- Чи має панель показувати `context_pack` / `delta` як інструменти, чи лише їх наявність.
