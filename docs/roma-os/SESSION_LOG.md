### Рішення

- `HANDOFF.md` — варіант A: блок «ПОТОЧНИЙ СТАН» зверху, файл не ріжемо.
- `/finish` Phase 0 — коміт **і push** одразу: cloud-контейнер ефемерний,
  локальний коміт не переживе обрив сесії.
- `session_id` = `YYYYMMDD-HHMM-<суфікс гілки>`. Якщо
  `.session-runtime.json` уже є — використовується той самий ID.
- Діапазон роботи сесії — `start_head..HEAD`.
  `git log <гілка> --not main` не використовується: гілка може бути вже
  змержена в `main` і команда покаже нуль комітів. Ця сесія — саме такий
  випадок (`start_head` == `start_main`).
- Межа: `STAGE-1.md` = «ще треба перевірити», `ISSUES.md` = «перевірили і
  знайшли дефект». Без дублювання.
- Нові правила в `CLAUDE.md` `/finish` не пише сам — тільки пропонує патч.
- Актуальний HEAD у документах не зберігається взагалі: документ, який сам
  комітиться, не може містити хеш власного коміту. У стані живе
  `work_end_head` (HEAD до службових docs-комітів `/finish`), а поточний
  HEAD `/start` бере через `git rev-parse HEAD`.
- Життєвий цикл `.claude/.session-runtime.json`: створює `/start`, видаляє
  тільки повністю успішний `/finish`. Залишений файл = попередня сесія не
  закрита, і нову поверх неї не починають.
- Жодне поле документа не фіксує стан, який змінюється самим записом:
  ні HEAD, ні номер прогону CI, ні те, що від них залежить.
